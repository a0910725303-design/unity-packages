# 操作回饋小遊戲製作指南

作者：Unity 套件編輯部。可作為原創遊戲規格，交給 AI 程式助手分階段實作。

**目標：** 製作「光點快遞」：玩家在單一小場景收集 10 顆能量，避開障礙並回到出口。整局約 2 分鐘，用同一套玩法比較有無回饋的差異。

文件免費，可用於個人或商業專案的規劃與實作。套件和美術需另行取得；本文件不含第三方授權，也不是已測試完成的遊戲工程。

## 1. 先看參考

- [Feel 官方示範與作品介紹](https://feel.moremountains.com/)：包括已上架的 Chill Snake 及各種互動示範。
- [Feel 網頁示範集](https://feel.moremountains.com/assets/resources/feel/builds/HTML/index.html)：比較不同回饋，但 WebGL 不展示所有平台能力。
- [Unity Boat Attack](https://github.com/Unity-Technologies/BoatAttack)：若選 URP，可參考官方專案如何組織場景與渲染功能。它是另一份賽艇示範，不是本原型的必要依賴。

本原型使用自己的規則與場景，不搬用以上作品的角色、關卡或美術。

## 2. 最小遊戲循環

1. 按「開始」進入 60 秒倒數。
2. 玩家以 WASD 移動，觸碰能量球後計數增加。
3. 碰到障礙損失 1 點生命，初始生命 3，受傷後有 1 秒無敵時間。
4. 收集 10 顆後開啟出口，回到出口勝利。
5. 時間歸零或生命歸零失敗，可立即重試。

場景可以是簡單 3D 俯視平台，使用球體、方塊與平面占位。先確認所選渲染管線，再決定材質與回饋，不為加入一個特效任意切換既有專案管線。

## 3. 套件分工

- **Feel：** 將音效、粒子、物件縮放與畫面效果組成事件回饋。
- **Unity 內建元件：** 移動、碰撞、計時、遊戲狀態與 UI。
- **URP（選用）：** 場景渲染；只有確定需要且已安裝時才加入相關後處理。

遊戲規則必須能在停用 Feel 後照常運作。分數不能靠音效或動畫播放完成才增加。

## 4. 回饋事件表

以下時間與幅度是起始設計值，需要實際試玩調整；不是套件預設值或效能保證。

| 事件       | 建議回饋                     | 初始時間     | 關閉動態效果時         |
| ---------- | ---------------------------- | ------------ | ---------------------- |
| 撿到能量   | 小粒子、短音效、計數文字縮放 | 0.15 秒      | 保留數字與靜態提示     |
| 受到傷害   | 玩家閃色、短音效、輕微震動   | 0.2 秒       | 取消震動，保留生命提示 |
| 能量集滿   | 出口亮起、提示音與文字       | 0.4 秒       | 保留出口標記與文字     |
| 最後 10 秒 | 計時文字變色、節制提示音     | 每秒最多一次 | 保留時間數字           |
| 勝利       | 結算面板淡入、短粒子         | 0.6 秒       | 直接顯示結算           |
| 失敗       | 操作停止、失敗面板淡入       | 0.3 秒       | 直接顯示失敗           |

不要以強烈閃爍或長時間震動取代清楚資訊。提供獨立的音量、震動強度與「減少動態效果」設定。

## 5. 責任與事件

這些名稱是自訂設計，不代表 Feel 現成類別：

- `RunState`：Ready、Playing、Won、Lost，狀態切換必須明確。
- `Collectible`：成功收集後先標記已消耗，再發送事件，避免同幀多次碰撞。
- `HealthController`：處理無敵時間與死亡，最後才通知表現層。
- `GameEvents`：傳遞收集、受傷、出口解鎖、勝敗等事件。
- `FeedbackAdapter`：監聽事件，呼叫已安裝版本可用的 Feel 播放元件。
- `AccessibilitySettings`：將設定映射到允許的回饋種類與強度。

具體元件名稱、參數與觸發方法請查閱 [Feel 官方文件](https://feel-docs.moremountains.com/)。不要讓 AI 根據舊文章猜目前版本 API。

## 6. 實作順序

### 交付一：沒有回饋也能玩完

完成角色移動、能量計數、受傷、計時與勝敗。用文字顯示狀態，確保一局能正常結束與重開。

### 交付二：加入事件回饋

一次只加一類回饋。先加收集，再加受傷，最後做結算。對高頻事件設上限或冷卻，避免同一瞬間疊加大量音效與震動。

### 交付三：對照與調整

提供開發用「全部回饋開／關」切換，用同一關卡比較。調整前先記錄感受與問題，例如計數看不清、震動太強、受傷沒有提示；每次只改一組參數。

### 交付四：重開與效能

重開時取消舊回饋並重置訂閱、計時與收集物。以目標裝置的 Profiler 檢查，不用編輯器幀率推論手機表現。大量重複粒子若造成分配尖峰，再引入物件池。

## 7. 可交給 AI 的提示

```text
依「光點快遞」規格做 Unity 小遊戲，先完成不含特效的遊戲循環。
規則層不得依賴 Feel 回呼。先記錄已安裝版本與渲染管線，保留既有設定。
接著用事件 adapter 加入收集與受傷回饋，附上場景元件的設定步驟。
實作減少動態效果及音量設定，關閉效果後仍能辨識所有重要狀態。
使用自製幾何占位物；不要下載付費素材或複製參考遊戲的內容。
說明已跑過的驗收與剩餘風險，不宣稱尚未測試的效能結果。
```

## 8. 驗收清單

- [ ] 同一能量球碰撞多次，只增加一次計數。
- [ ] 無敵期間不重複扣血，生命與時間不出現負值。
- [ ] 同幀觸發勝利與失敗時，有明確且一致的優先順序。
- [ ] 完全停用回饋後仍可完成一局，數值結果不變。
- [ ] 連續觸發音效與震動不會無限制累加。
- [ ] 減少動態效果開啟後，沒有鏡頭震動，仍有文字和靜態提示。
- [ ] 連續重開 10 次不重複訂閱事件，不殘留舊倒數或粒子。
- [ ] 不同視窗比例下，生命、時間與出口提示都能閱讀。
- [ ] 在目標裝置測量後才記錄效能結果，未測平台標記待驗證。
