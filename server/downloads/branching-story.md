# 分支敘事 RPG 製作指南

作者：Unity 套件編輯部。這份原創規格適合手動製作，或分階段交給 AI 程式助手實作。

**目標：** 製作「燈塔失物事件」：玩家在暴雨前找回燈塔鑰匙，訪問兩名角色、取得三條線索，最後決定相信誰。第一版約 10 分鐘，可重玩並查看不同結果。

文件免費，可用於個人或商業專案的規劃與實作。不附第三方套件或遊戲素材，套件授權需自行取得。這是製作與驗收指南，並非已測試的 Unity 專案。

## 1. 作品參考

- [Disco Elysium 官方作品頁](https://discoelysium.com/)：觀察文字閱讀、角色對話和選項節奏。
- [Dialogue System 作者的工具流程說明](https://forum.pixelcrushers.com/post/whats-the-easiest-text-tool-for-importing-to-dialogue-system-13719656)：作者確認該作品搭配 articy:draft 使用 Dialogue System。
- [Heaven’s Vault 官方頁](https://www.inklestudios.com/heavensvault/)：Adaptive narrative 段落解釋 ink 如何回應玩家選擇。
- [The Intercept 官方示範](https://www.inklestudios.com/ink/theintercept/)與[完整 Unity 專案](https://github.com/inkle/the-intercept)：適合研究短篇故事與程式的連接方式。

參考的是互動形式；本文件的角色、情節與規則另行設計。

## 2. 先選敘事核心

| 路線 | 核心                      | 工作方式                                                          |
| ---- | ------------------------- | ----------------------------------------------------------------- |
| A    | Dialogue System for Unity | 依安裝版本文件建立對話資料、條件、事件與 UI；第一版可用內建編輯器 |
| B    | ink + Unity integration   | 用 ink 撰寫故事，Unity 顯示文字和選項，處理場景互動及存檔         |

故事狀態只由一個核心管理。不要讓 Unity boolean 和敘事變數各自保存一份真相。若另接劇本編輯工具，先用一段對話測試匯入，不一次搬入整部劇本。

開始前確認 Unity 版本、輸入方案與實際套件版本。使用已安裝文件確認 API；以下名稱只是自訂規格。

## 3. 故事與場景

場景只需燈塔門口、倉庫、碼頭三個區域。使用原創文字與幾何占位物即可。

- 管理員「安禾」：急著點亮燈塔，認為搬運工拿走鑰匙。
- 搬運工「路寧」：承認進過倉庫，但說是去修漏水的窗。
- 線索一：倉庫窗邊的濕繩，顯示有人剛修過窗。
- 線索二：管理員的工作簿，記錄鑰匙最後在工具箱。
- 線索三：碼頭收據，證明搬運工離開時間早於鑰匙失蹤。

不要把原型擴張成戰鬥、物品合成或大世界遊戲。先讓完整故事能走完。

## 4. 狀態規格

| 穩定 ID      | 類型／初始值 | 用途                          |
| ------------ | ------------ | ----------------------------- |
| clue_rope    | bool / false | 已查看濕繩                    |
| clue_log     | bool / false | 已查看工作簿                  |
| clue_receipt | bool / false | 已查看收據                    |
| trust_worker | int / 0      | 搬運工信任，範圍 -1 到 1      |
| key_found    | bool / false | 已找到鑰匙                    |
| ending       | enum / none  | repaired、delayed、unresolved |

顯示文字可以改，ID 不因翻譯或改名而改。已讀紀錄、線索、結局旗標要能儲存。

## 5. 對話與分支表

| 節點       | 可選行動     | 條件                       | 狀態／後續          |
| ---------- | ------------ | -------------------------- | ------------------- |
| 管理員初訪 | 詢問工作流程 | 無                         | 提示倉庫工作簿      |
| 搬運工初訪 | 先聽解釋     | 尚未決定態度               | trust_worker = 1    |
| 搬運工初訪 | 直接指責     | 尚未決定態度               | trust_worker = -1   |
| 搬運工再訪 | 出示收據     | clue_receipt               | 提供工具箱位置      |
| 工具箱     | 搜尋鑰匙     | clue_log 或取得位置提示    | key_found = true    |
| 最後對質   | 一起修復燈塔 | key_found 且有兩條以上線索 | ending = repaired   |
| 最後對質   | 只交鑰匙     | key_found                  | ending = delayed    |
| 最後對質   | 暫時離開     | 無                         | ending = unresolved |

態度選擇只結算一次，重新開啟對話不重複加減信任。任何路線都保留找鑰匙的替代途徑，避免單次選錯造成無意義的死局。

## 6. 程式與 UI 責任

- `StoryAdapter`：將敘事核心輸出轉為「文字、說話者、可選答案、事件」。
- `DialogueView`：顯示文字與選項，支援鍵盤與滑鼠；不自行決定分支條件。
- `InteractionController`：控制可互動範圍，對話時停止角色移動。
- `WorldEventHandler`：接收開門、取得線索等具名事件；重複事件必須安全。
- `StorySaveService`：一起保存敘事核心狀態、世界狀態、場景與 schema 版本。

這些是專案自訂責任名稱，不是套件 API。只透過 adapter 呼叫已確認的套件方法。

## 7. 製作順序

1. 用純文字完成所有分支，畫出每條結局可達的路線。
2. 只接一名 NPC，跑通「開始對話 → 選答案 → 結束 → 恢復操作」。
3. 加入線索旗標與條件選項，驗證重訪時文字正確。
4. 加入場景事件及三個結局，保持狀態寫入只有一個入口。
5. 在安全節點存檔。先支援結束對話後存檔，再評估中途儲存需求。
6. 加上文字速度設定、略過打字效果、對話紀錄及選項焦點標示。

## 8. 可交給 AI 的提示

```text
依照「燈塔失物事件」規格製作 Unity 分支故事原型。
先檢查已安裝的 Dialogue System 或 ink，選定一個敘事真實資料來源。
第一步只做一名 NPC、兩個選項與一次世界事件，使用自有 StoryAdapter。
不要猜套件 API，請依目前專案文件或程式碼確認。
不要產生其他遊戲的角色、美術或劇情。使用本文件的原創情境與占位物。
交付時列出場景掛載步驟、可重現操作、已測試結果與未驗證部分。
```

## 9. 驗收清單

- [ ] 三種結局各有一條可重現操作路線。
- [ ] 沒有線索時不出現需線索的選項，取得後可正常出現。
- [ ] 重複交談、重新讀檔不重複結算信任或發放鑰匙。
- [ ] 對話結束後角色可移動，對話中不誤觸場景操作。
- [ ] 連點下一句不會跳過選項或同時執行兩個分支。
- [ ] 存讀檔後，場景物件與敘事旗標一致。
- [ ] 中文換行、長選項與不同視窗比例不遮擋文字。
- [ ] 失敗或保留結局也有明確結束畫面與重新開始入口。
