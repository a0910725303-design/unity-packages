# 回合戰術遊戲原型製作指南

作者：Unity 套件編輯部。這份原創規格可以由人或 AI 程式助手分階段實作。

**目標：** 製作「補給車護送」：兩名隊員在 10 × 10 格地圖上護送補給車抵達出口。玩家移動、攻擊、結束回合，再觀察敵人的行動。

文件免費，可用於個人或商業專案的規劃與實作。第三方套件需另行取得授權；不附商業遊戲素材或完整工程。本文件是待實作與驗收的設計，沒有宣稱套件組合已完成相容性測試。

## 1. 參考作品與工具分工

- [Phantom Brigade 開發團隊的 Odin 訪談](https://odininspector.com/blog/brace-yourself-games-phantom-brigade)：參考資料配置與自訂 Inspector 的做法。
- [A* Pathfinding 官方作品案例](https://arongranberg.com/astar/)：包括 Darkwood、Cult of the Lamb 等遊戲，證明尋路工具的應用範圍。
- [DOTween Showcase](https://dotween.demigiant.com/showcase.php)：可查看使用補間工具的成品。

| 套件                   | 在本原型負責             | 自己仍要製作                       |
| ---------------------- | ------------------------ | ---------------------------------- |
| A* Pathfinding Project | 路線查詢與導航圖         | 回合、行動點、占位、攻擊與勝負規則 |
| Odin Inspector         | 整理與檢查開發資料       | 遊戲運行中的 UI 和戰鬥邏輯         |
| DOTween                | 選取提示、移動及 UI 過場 | 合法行動判斷、數值結算、取消流程   |

本原型採傳統交替回合，並非重製 Phantom Brigade 的同步時間軸系統。工具案例也不代表上表的整套組合曾用於某款遊戲。

## 2. 範圍與數值

- 10 × 10 棋盤，少量不可通行的箱子。
- 兩名隊員、三名敵人、一台補給車。
- 隊員每回合 2 AP；移動每格 1 AP；攻擊花費 1 AP，射程 3 格，傷害 2。
- 隊員生命 6、敵人生命 4、補給車生命 8。
- 補給車每個玩家回合結束時，若前方可通行便前進 1 格。
- 補給車抵達出口勝利；補給車毀壞或兩名隊員都倒下失敗。

以上為原型設計值。第一版固定命中、無高低差、無機甲拼裝、無裝備掉落，不加入機率命中來掩蓋規則錯誤。

## 3. 系統責任

以下為自訂類別概念，具體套件呼叫需依已安裝版本確認：

- `BoardState`：格子地形、占位與出口位置，作為戰鬥座標的真實來源。
- `UnitState`：穩定 ID、陣營、格子、生命、AP 與存活狀態。
- `PathAdapter`：把套件路線轉成合法格子序列；處理查詢失敗或過期結果。
- `CommandValidator`：執行前重新檢查回合、AP、路線、目標與占位。
- `BattleController`：序列執行命令、扣 AP、更新資料並觸發表現。
- `BattleView`：呈現資料；動畫停止或跳過不能改變戰鬥結果。
- `TurnController`：管理 PlayerTurn、Resolving、EnemyTurn、Victory、Defeat。

不要用物件 Transform 當作唯一棋盤資料。角色走到畫面中間時，也應能知道它原本在哪格、要去哪格，以及該命令是否已結算。

## 4. 路線與占位

1. 滑鼠指到格子時預覽路線及成本，不扣 AP。
2. 按下移動時重新驗證，因為目標或占位可能已改變。
3. 僅接受每步相鄰且可通行的格子序列，第一版不走對角線。
4. 路線到不了目標就顯示原因，不把部分路徑當作成功抵達。
5. A* 的路徑長度不直接當 AP；把路線轉為棋盤步數後計算成本。
6. 動態占位可由自身棋盤驗證處理；若修改套件導航圖，依安裝版本文件等候更新完成。

先做無動畫的規則測試，再加移動補間。場景卸載或角色死亡時停止相關動畫，避免回呼再次結算。

## 5. 敵人規則

敵人按穩定順序輪流行動：若射程內有目標則攻擊；否則走向最近可達的玩家單位；都不可達則待機。相同距離以單位 ID 排序，方便重現測試。

每次只執行一個敵人命令，完成後再處理下一個。當勝負條件成立，停止剩餘排程與輸入。

## 6. 資料編輯與驗證

用 ScriptableObject 保存單位與關卡設定。若使用 Odin，優先整理生命、AP、武器與關卡資訊的分組，再依實際可用屬性增加編輯提示。

資料載入時仍必須驗證：生命大於 0、AP 非負、出口在棋盤內、初始單位不重疊。Inspector 提示不能取代運行時資料驗證。

## 7. 三次交付

1. **規則切片：** 棋盤、兩名隊員、AP、合法移動、結束回合。無動畫。
2. **完整戰鬥：** 敵人、攻擊、死亡、補給車、勝負。能完整玩一局。
3. **表現與工具：** 路線預覽、DOTween 動畫、Odin 整理、重開關卡。

每次只在前一階段驗收通過後繼續。先保留固定種子的測試關卡，避免隨機布局讓錯誤難以重現。

## 8. 可交給 AI 的提示

```text
依本文件建立「補給車護送」Unity 原型，先完成無動畫的規則切片。
先確認 Unity、A*、Odin、DOTween 的實際版本；缺少套件時說明並提供清楚隔離的替身路線。
棋盤狀態與視覺分離。移動前後都驗證占位，動畫回呼不得重複扣 AP。
只實作固定命中和交替回合，不加同步時間軸或裝備養成。
交付可重現的操作流程與實際驗證結果，不把未跑過的檢查寫成通過。
```

## 9. 驗收清單

- [ ] 不能走入障礙、其他單位所在格或棋盤外。
- [ ] AP 不足的命令不改變位置、生命或 AP。
- [ ] 動畫中連點不會排入未授權的第二個命令。
- [ ] 相鄰格、最遠合法格與不可達格的預覽和結果一致。
- [ ] 已死亡單位不能行動，也不阻塞後續回合。
- [ ] 敵人找不到路仍會結束回合，不無限等待。
- [ ] 勝利或失敗後所有戰鬥輸入停止，重新開始可回到初始狀態。
- [ ] 中途切換場景不留下動畫回呼、錯誤占位或空參考例外。
